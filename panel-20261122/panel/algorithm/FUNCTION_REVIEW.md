## Safety and semantic obligations examined in more depth

### Scanner padding and unsafe field reads

`EventLines::line` loads four/eight bytes from event-type pointers even when a field is shorter. AVX2 ID/product handling can also read beyond the logical field. Inspection of `scan::fused` shows that only a prefix with at least `2*PAD` bytes remaining in the backing allocation is scanned directly. The last complete-row tail is copied into initialized zero padding before callbacks. Thus the call sites have backing storage beyond a short field, including end-of-file cases. This is a concrete prerequisite; these callbacks must not later be reused on arbitrary unpadded slices. `page_boundary_end` and scanner tests cover important boundary cases, but do not replace an unsafe-code proof or sanitizer run.

### Publication, prefetched pointers and manual mapping lifetimes

The canonical-person table is built once and published before click resolution and dedup. Prefetch computes a bounded slot in this still-live table. The event parse sinks are finished before `p1_ready` release/acquire publication; all p2/click sinks are complete before the barrier leading to grouping. Sink flushing includes the fence needed after streaming stores. One atomic queue claim owns each dedup partition, so its blocks are recycled only by that owner after all records needed by later steps have been copied.

Per-worker `Arena::release` occurs only after the final-job loop observes that every worker has submitted its finished result. Submission occurs after that worker has finished all person-partition reads. This condition matters because recycled blocks can originate in a different worker's arena: freeing an arena immediately after its owner's local work would be unsafe. The inspected orchestration retains the required global completion condition.

File unmapping similarly depends on the last consumer count and on not retaining string slices into the mapped input. Reference-table files are separately leaked for the process lifetime; encoded event/click/link records do not retain input slices. The process is deliberately one-shot and exits explicitly. Reusing `run` as a long-lived library API would require a separate ownership/lifetime design.

### Exact deduplication is preserved

The bitmap is a collision prefilter, not a probabilistic answer. All copies of one exact event ID hash to the same partition and bitmap slot; any repeated slot goes through exact-key dedup. An unrelated collision merely promotes additional candidates. Invalid payload copies are retained with their ingest timestamp so an earlier invalid event suppresses a later valid copy. Candidates and ring entries are owned values by the time the source blocks can be recycled. Sentinel keys, fixed-width payloads and full exotic-ID identity were checked through their defining contracts.

### Integer and workload bounds

The fast path rejects windows that do not fit its u32 relative timestamp domain and falls back when categories exceed its packed representation. Valid purchase prices fit 24 bits. Session/day revenue uses u64. Event/person/click prefix sums, local IDs and original-event link indices remain u32; these are valid for the official 20M/60M scale, not a promise to process an arbitrary number above 2^32 in one partition. Nonnegative relative times plus sorted bins/clicks justify the unsigned subtractions. Session-start day, not each purchase's individual date, indexes daily outputs.

### What this review does not establish

No formal UB/race proof, sanitizer run, Miri run, performance causality or official leaderboard speedup is claimed here. The body-level review found no new blocker and identifies the invariants that must remain true. Complete candidate execution results and benchmark conditions belong in the coordinator's pinned evidence ledger. The original pipeline's broader numerical range and one-shot process assumptions remain inherited limitations; they were not silently expanded by the optimization.
