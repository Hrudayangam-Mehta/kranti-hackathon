# Rust support modules: function-by-function review

## Scope and meaning of status

Reviewed source: `experiments/bins-purchases/src/fast/{id,keys,scan,sink,ts,people}.rs`, copied without changes to these modules from the live C submission at `ad8526b3410bfb6b8b8febff35affe6bd5b42499`. File hashes and an exact declaration inventory are recorded in the adjacent `FUNCTION_REVIEW_SOURCE.json`.

Every production function and unsafe kernel in these six files was read. Test-only helper functions and test entry points are grouped explicitly below. `Reviewed` means static inspection of the stated property; it is not a formal proof or a claim that this worker personally executed that test. The parent/database reviewers own executed-test receipts. `Unresolved` identifies a remaining API-generalization or test-portability limitation and explains whether it affects the current concrete pipeline.

Test references below name existing Rust test modules plus the independently executed pipeline fixtures/adversarial harness where applicable. SIMD functions require both sufficient readable padding and the runtime CPU-feature gate. Arena-backed views must not outlive the mapped storage. Those caller obligations are reviewed explicitly rather than inferred from a successful output comparison.

## Review conclusions

The inspected production paths preserve exact opaque-string identity and use hashes only for routing/probing. SIMD and SWAR paths retain scalar differential implementations. The manual lifetime and alignment obligations are localized in scanner, arena and sink code and were checked against actual call sites and concrete record layouts.
